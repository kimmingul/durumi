# v0.3 SPEC-1 릴리스 게이트 — AC-WS-024 수동 한글 IME 스모크

> AC-WS-024는 자동화로 대체할 수 없다(`acceptance.md:283-287`,
> `product.md` §8 게이트 3, `docs/DOCUMENT_MODE_PRINCIPLES.md` §2). CDP
> `Input.imeSetComposition`은 OS 변환 계층(한자 변환 등)을 재현하지 못하므로,
> 실제 macOS 한글 2벌식 IME로 이 절차를 **사용자가 직접** 수행해야 한다.
> 소요 시간 약 10-15분. 각 단계는 그대로 따라 할 수 있도록 명령/키 입력
> 수준으로 적었다.

## 사전 준비

1. macOS 입력 소스에 **한글 2벌식**이 추가되어 있는지 확인 (시스템 설정 >
   키보드 > 입력 소스). 없으면 추가 후 `⌘ + Space` 또는 `Ctrl + Space`로
   전환 가능한 상태로 둔다.
2. 터미널에서 임시 프로젝트 디렉터리를 만들고 매니페스트 + 원고 파일을 준비한다:

   ```bash
   mkdir -p /tmp/durumi-ime-smoke/manuscript
   cd /tmp/durumi-ime-smoke
   cat > .durumi-project.yaml <<'EOF'
   name: IME 스모크 테스트 프로젝트
   authors: 김민걸
   EOF
   cat > manuscript/draft.md <<'EOF'
   # 스모크 테스트 원고

   외부 변경 조정 테스트를 위한 첫 줄입니다.
   EOF
   ```

3. Durumi를 빌드된 앱으로 실행하거나 개발 모드로 실행한다:

   ```bash
   pnpm dev   # 또는 배포된 DMG에서 실행
   ```

4. File > Open... (`⌘O`)으로 `/tmp/durumi-ime-smoke/manuscript/draft.md`를 연다.
5. 문서모드(Document mode, `⌘1`)로 전환하고, 캐럿을 "첫 줄입니다." 문장 끝에
   둔다.

## 절차 A — 다단계 조합 중 외부 파일 변경

1. 캐럿을 문장 끝(마침표 뒤)에 두고 한글 2벌식으로 **여러 음절에 걸친
   조합**을 시작한다 — 타이핑: `ㅇ ㅏ ㄴ ㄴ ㅕ ㅇ` (안녕을 의도하되, 마지막
   음절 `녕`을 완성하기 직전 상태 — 즉 `안녕`까지 확정하지 말고 `녕`이 아직
   조합 중(밑줄 표시)인 상태로 멈춘다). macOS IME는 조합 중인 음절에 밑줄을
   표시하므로 밑줄이 보이는 시점에서 다음 단계로 진행한다.
2. **조합을 유지한 채로**(밑줄이 사라지지 않은 상태에서) 별도 터미널 창을
   열고 같은 파일을 외부 프로세스로 수정한다:

   ```bash
   echo "외부 프로세스가 추가한 줄." >> /tmp/durumi-ime-smoke/manuscript/draft.md
   ```

3. 1-2초 대기한다(감시 debounce). Durumi 창으로 포커스를 옮기지 말고 그대로
   관찰한다.
4. **관찰해야 할 것 (조합 유지 중)**:
   - [ ] 조합 중이던 음절(밑줄 표시)이 **소실되거나 중복되지 않는다** — 정확히
     입력한 대로 밑줄 상태가 유지된다.
   - [ ] 편집기 포커스와 캐럿 위치가 바뀌지 않는다.
   - [ ] 외부 변경이 즉시 버퍼에 반영되지 않는다 (조합 중에는 보류되어야 한다).
   - [ ] 화면 어딘가(보류 표시 또는 상태 표시줄)에 "외부 변경 대기 중" 류의
     비침습 표시가 나타날 수 있다 — 모달 대화상자는 **나타나지 않아야 한다**.
5. 조합을 **완성하고 확정**한다 — `Space` 또는 `Return`을 눌러 `안녕`을
   커밋한다 (또는 자연스럽게 조합을 끝맺는 키 입력).
6. **관찰해야 할 것 (조합 확정 직후, 같은 턴 이내)**:
   - [ ] 방금 커밋한 `안녕` 텍스트가 문서에 정확히 남아 있다 (음절 소실·중복
     없음).
   - [ ] 보류되어 있던 외부 변경 결과가 **같은 턴에** 표면화된다 — 이 버전
     기준으로는 외부 변경 배너(비침습 알림)가 나타나야 한다(미저장 편집이
     있으므로 자동 반영이 아니라 배너로 라우팅되는 것이 정상 — AC-WS-020).
   - [ ] 배너가 나타났다면, 배너에 표시된 "적용" 동작을 눌러 외부에서 추가한
     "외부 프로세스가 추가한 줄."이 문서 끝에 반영되는지 확인한다.
   - [ ] 모달 대화상자(`role="dialog"` 스타일의 화면 차단 팝업)가 나타나지
     않았다.

## 절차 B — 조합을 취소한 경우 (hold-and-forget 확인)

1. 새 문단에 캐럿을 두고 다시 한글 2벌식 조합을 시작한다 (예: `ㄱ ㅏ` 입력
   중 밑줄 상태).
2. 조합이 유지된 상태에서 절차 A와 동일하게 외부 터미널로 파일을 수정한다:

   ```bash
   echo "두 번째 외부 변경." >> /tmp/durumi-ime-smoke/manuscript/draft.md
   ```

3. 1-2초 대기 후, 조합을 **완성하지 않고 취소**한다 — `Esc`를 눌러 조합
   중이던 음절을 지운다 (macOS 한글 입력기는 `Esc`로 조합을 취소하면 조합
   중이던 글자가 지워진다).
4. **관찰해야 할 것**:
   - [ ] 취소 후 문서에 조합 중이던 글자 잔여물이 남지 않는다.
   - [ ] 보류되어 있던 외부 변경이 **소리 없이 사라지지 않는다** — 조합을
     커밋했을 때와 마찬가지로 같은 턴에 정책 결과(배너 또는 조용한 반영)가
     나타나야 한다. 아무 표시도 없이 보류 표시만 사라지면 **FAIL**이다(무성
     소실 — 사용자가 외부 변경이 무시된 것으로 오인하는 경로).

## 실패 시 기록 방법

아래 항목이 하나라도 실패하면 다음을 기록하고 이슈로 등록한다:

1. **재현 스텝**: 위 절차 A/B 중 어느 단계에서 재현되었는지 정확한 단계 번호.
2. **입력한 정확한 자모/음절 시퀀스**와 **실제로 문서에 남은 텍스트**를
   나란히 기록 (음절 소실/중복 여부 판정용).
3. **macOS 버전 + 입력 소스 이름** (예: "한글2벌식" vs "한글2벌식(구형)" 등
   변형이 여러 개 있을 수 있음).
4. 가능하면 화면 녹화(QuickTime 화면 기록, `⌘ + Shift + 5`)를 남긴다 — 조합
   중 밑줄 상태는 스크린샷 한 장으로는 타이밍을 판단하기 어렵다.
5. `docs/DOCUMENT_MODE_PRINCIPLES.md` §2 "Anti-pattern" 절에 이미 기록된
   패턴(4-cycle false-green)과 일치하는지 대조한다 — 자동화 e2e
   (`e2e/reconciliation-ime.spec.ts`, `e2e/composition-primitive.spec.ts`)가
   초록인데 이 수동 스모크만 실패한다면, 그것이 바로 이 게이트가 존재하는
   이유다.

## 2. 계층 배치

3-프로세스 + `shared/` 커널 구조를 **변경하지 않고** 새 책임을 배치한다.

```
┌─ shared/ ─────────────────────────────────────────────┐
│  매니페스트 스키마·검증·키 범위 계산                     │
│  front matter 키 스키마 (author / registration /       │
│                          acknowledgements)             │
│  메타데이터 유효값 계산 (front matter 정본 +           │
│                          매니페스트 기본값) — 순수 함수  │
│  폴더 규약 상수 · IPC 계약(신규 채널)                    │
└───────────────┬───────────────────────┬───────────────┘
                │                       │
┌─ electron/ ───▼──────────┐   ┌─ src/ ─▼──────────────┐
│  프로젝트 discovery       │   │  조정 정책 (교체 가능) │
│   (walk-up, 32단계)       │   │  IME 게이트 + 보류 큐  │
│  파일·폴더 감시            │IPC│  배너 상태             │
│  변경 확정 (mtime+size)   │◄─►│  최소 diff 적용        │
│  경로별 debounce          │   │                       │
│  자기 저장 에코 억제       │   │                       │
└──────────────────────────┘   └───────────────────────┘
```

배치 근거는 강제된 것이지 취향이 아니다:
- **파일시스템은 main 전용** — 렌더러는 `sandbox: true`, Node API 없음
- **조합 상태는 렌더러 전용** — main은 조합 여부를 알 수 없다. 따라서 IME 게이트는 반드시 `src/`
- **양쪽이 같은 타입을 봐야 하는 것만 `shared/`** — 매니페스트 스키마, 메타데이터 계산

### 2.1 제약 — `shared/`는 `electron/`을 import할 수 없다

`tsconfig.web.json`이 `composite: true` + `include: [src/**, shared/**]`이므로 `shared/` → `electron/` import는 TS6307로 실패한다(`research.md` §6.2).

**설계 결과**: 폴더 규약 상수를 `shared/`에 두면 `REFERENCE_DIR_NAME`(현재 `electron/referenceFs.ts:18`)을 참조할 수 없다. M1이 택할 두 경로:

| 안 | 내용 | 평가 |
|---|---|---|
| (a) 상수를 `shared/`로 이동, `electron/referenceFs.ts`가 재export | SSOT 단일화 | 권장. 기존 import 경로 변경 수반 |
| (b) `shared/`에 독립 선언 | 변경 최소 | 두 정의가 드리프트할 수 있음. `StyleSet` 중복(`structure.md` §10)과 같은 함정 |

두 값의 동일성 단언은 어느 안이든 **테스트 계층**(`tsconfig.test.json`은 비-composite + node 타입)에 둔다.

## 3. 감시와 확정 — "이벤트는 신호, 진실은 재검사"

핵심 설계 원리 하나가 여러 요구를 동시에 만족시킨다:

> 감시 이벤트는 **"뭔가 바뀌었을 수 있다"는 신호로만** 쓰고, 실제 판정은 항상 mtime + size 재검사로 한다.

이 원리가 해결하는 것:

| 문제 | 이 원리가 주는 해답 |
|---|---|
| macOS/Windows 이벤트 형태 차이 (`research.md` §2.2) | 형태 차이가 확정 이벤트에 새지 않는다 — 재검사 결과만 위로 올라간다 |
| 자기 저장 에코 (`research.md` §2.5) | 저장 직후 mtime/size를 기록해두고 재검사 값과 대조하면 판별된다. 감시 일시 중지 같은 시간 창 트릭이 불필요 |
| 내용이 같은 재작성 | 재검사에서 걸러진다 |
| Windows e2e 부재 (C-6) | 재검사를 순수 함수로 분리하면 두 플랫폼 이벤트 시퀀스를 유닛에서 재현 가능 |

### 3.1 경로별 debounce

현행 루트당 스칼라 방식(`research.md` §2.3)을 경로별 독립 합류로 교체한다. 최소 형태는 `Map<경로, 타이머>`이며, 합류 창 만료 시 그 경로만 재검사한다.

Linux 폴링 분기는 경로 단위 방출로 승격하거나(스냅샷이 이미 경로별 맵이므로 저비용) Linux에서 조정을 비활성화한다 — M4가 명시 선택한다. "현행 유지"는 계약 위반 코드를 남기는 것이므로 선택지가 아니다.

### 3.2 data 역할 경로 제외는 역할 기반

리터럴 `data/` 제외가 아니라 **`folders`가 data 역할에 대해 해석한 경로 하나**를 제외한다. `folders.data: archive` + `folders.manuscript: data` 같은 설정에서 리터럴 기준으로 제외하면 원고 폴더 감시가 꺼져 REQ-WS-045를 위반한다.

## 4. IME 게이트 — 이 SPEC의 구조적 핵심

### 4.1 왜 게이트가 렌더러에 있어야 하는가

main은 조합 여부를 모른다. main이 "확정됨"을 알리고 렌더러가 "지금 라우팅해도 되는가"를 판정하는 분할이 유일하게 성립하는 구조다.

```
main: 감시 → 재검사 → 확정 ──IPC──► renderer: 조합 중?
                                          │
                        ┌──── 아니오 ─────┘
                        │                 └──── 예 ──► 보류 큐 (최신 1건만 유지)
                        │                                    │
                        │                             compositionend
                        │                                    │
                        ▼                                    ▼
                  ┌─────────────────────────────────────────────┐
                  │  정책 라우터 (REQ-WS-029)                    │
                  │  버퍼가 dirty?                               │
                  │    아니오 → 최소 diff 적용 (REQ-WS-024)      │
                  │    예     → 배너 (REQ-WS-027, 버퍼 불변)     │
                  └─────────────────────────────────────────────┘
```

**게이트는 라우팅을 지연시킬 뿐 결과를 결정하지 않는다.** 두 경로가 같은 정책 라우터로 합류하는 것이 이 다이어그램의 핵심이다. 이전 판은 `compositionend ─► 적용`으로 그려 조합 종료가 곧 적용인 것처럼 보였는데, 이는 D-2(미저장 편집이 있으면 버퍼를 교체하지 않는다) 확정 **이전**의 그림이었다. 조합으로 커밋된 텍스트는 그 자체가 미저장 편집이므로, 텍스트를 남긴 조합이 끝나면 라우터는 **항상** 배너를 고른다. 게이트를 우회해 버퍼에 직접 쓰는 경로는 존재하지 않는다.

### 4.2 조합 상태 관찰

`src/editor/decorations/table.ts:810-926`이 유일한 실행 코드 선례다 — 요소에 `compositionstart`/`compositionend` 리스너를 걸고 `dataset.composing` 플래그를 유지하며 `ev.isComposing`도 함께 본다. **그 구현은 표 셀 전용**이므로 에디터 일반 표면용 조합 상태는 신규 구축이며, 방식만 이 선례와 일관되게 한다.

### 4.3 모달 금지는 IME 결정이지 UX 취향이 아니다

모달은 포커스를 강제 이동시켜 조합을 중단시킬 수 있다. `pendingInlineFormat.ts:12-32`가 "조합 도중 문서를 고치면 IME의 composing-range 추적이 깨진다"를 실증하고 그 대가로 기능 하나를 포기한 기록이므로, 조정 알림 표면에서 모달을 구조적으로 배제한다.

### 4.4 검증 가능성이 설계에 미친 영향

현행 `composeKorean`은 원자적이라 조합을 열어둘 수 없고, 저장소의 CDP IME e2e 커버리지는 실제로 0이다(`research.md` §3.1, §3.2). 따라서 **테스트 하네스 자체가 이 SPEC의 산출물**이 된다:

| 요소 | 역할 |
|---|---|
| `startComposition(page, text)` | 세션을 detach하지 않고 조합을 연다 + `compositionend` 카운터 설치 |
| `updateComposition(handle, text)` | 다단계 조합 근사 |
| `endComposition(handle)` | 조합 종료 + detach |
| `observeCompositionEnd(handle)` | 카운터 노출 — **"조합이 조기 종료되지 않았다"의 유일한 관측 수단** |

네 번째 요소가 없으면 단언할 대상이 없다(범용 조합 플래그 부재). 관측 수단을 계약에 포함시키는 것이 설계 결정이다.

**정직한 한계**: CDP 교체 semantics ≠ 실제 macOS IME `compositionupdate`. 따라서 자동 AC는 재현 가능한 것(조합 경계 유지, 커밋 텍스트 바이트 일치)만 단언하고, "음절 소실·중복 없음"은 수동 스모크(AC-WS-024)에 남긴다.

## 5. 조정 적용 — 전체 교체가 아니라 최소 차이

버퍼 전체 교체는 캐럿·선택·스크롤·실행 취소를 모두 무의미하게 만든다. CodeMirror 6 트랜잭션은 변경 범위로 selection을 자동 매핑하므로, **디스크 내용과 현재 버퍼의 공통 접두/접미를 잘라낸 단일 replace**만으로도 대부분 만족된다.

단계적 접근: 공통 접두/접미 축약 → (캐럿 보존이 불충분할 때만) 라인 단위 diff. 처음부터 diff 라이브러리를 들이지 않는다.

## 6. 확장 seam — SPEC-4가 확장할 지점

조정 정책을 교체 가능한 객체로 만든다. 확정 이벤트는 정책을 거쳐 라우팅된다.

```
확정 이벤트 ──► 정책 객체 ──┬─► 자동 반영        (미저장 편집 없음)
                            ├─► 배너 알림        (미저장 편집 있음)
                            └─► 승인 대기 큐     (SPEC-4가 주입)
```

이 seam이 없으면 SPEC-4가 조정 계층을 재작성해야 한다. 배너(REQ-WS-027)는 SPEC-4의 승인 표면이 확장할 UI 기반이기도 하다.

## 7. 메타데이터 — 3계층과 그 귀결

```
원고 front matter  (정본)      author / registration / acknowledgements
        │ **미기입이 아닌 값**이면 아래를 완전히 억제 (경고 없음 — 정상 동작)
        │ 미기입이면(없음/null/""/"  "/[]) 아래로 통과 — REQ-WS-054
        ▼
매니페스트         (기본값)     authors / registration / acknowledgements
        ▼
.bib 파일          (서지 정본)  위 두 계층은 서지 항목을 담지 않는다
```

### 7.1 억제는 충돌이 아니다

이전 판은 두 값의 불일치를 충돌로 보고 경고했다. D-4 반전 이후 front matter 선언은 **의도된 문서 수준 선언**이므로 경고 대상이 아니다. 원고가 여러 편이고 저자가 다른 것이 이 설계가 존재하는 이유다.

### 7.1a 억제 판정은 값 기반이다 (판 0.2.2 — M1이 드러낸 결함)

```
front matter 키를 읽는다
      │
      ├─ 값이 미기입인가? (없음 / null / "" / "  " / [] / 전부 빈 시퀀스)
      │        │
      │        ├─ 예 → 매니페스트 기본값 채택 ─┐
      │        └─ 아니오 → front matter 값 채택 ┤
      │                                          │
      └──────────────────────────────────────────▼
                                        유효값 확정 → 형식 검증은 여기서만
```

**키 존재 기반이면 안 되는 이유**: 출하 템플릿이 모든 원고에 `author: `를 발행한다. 키 기준으로 억제하면 템플릿에서 만든 원고 전부가 매니페스트 기본값을 받지 못해 **기본값 계층이 정상 생성 경로에서 죽는다**.

**null이 판정에 반드시 포함되어야 하는 이유**: `author: `는 빈 문자열이 아니라 **`null`로 파싱된다**(`js-yaml` `JSON_SCHEMA` 실측). 빈 문자열만 미기입으로 보면 출하 템플릿의 실제 형태가 걸러지지 않아 결함이 그대로 남는다. 이것이 REQ-WS-054가 형태를 표로 열거하는 이유다.

**`registration`도 같은 구조를 갖는다**: 템플릿이 발행하는 `ClinicalTrials.gov NCT` / `PROSPERO CRD`는 빈 값이 아니지만 식별자가 비어 있는 자리표시자다. REQ-WS-055가 이를 `registration`의 미기입 형태로 규정한다 — 그러지 않으면 CONSORT / PRISMA 원고가 프로젝트 등록번호를 상속받지 못한다.

**대가**: "의도적으로 저자 없음"을 표현할 수단이 없다. 빈 값은 항상 "아직 안 씀"이다. 인지된 상태로 수용한다.

### 7.2 검증은 채택된 값에만

형식 검증을 계층 해석 **이후** 유효값에만 적용한다. 그렇지 않으면 유효한 NCT를 선언한 원고가 쓰이지도 않는 매니페스트의 낡은 placeholder 때문에 경고를 받는다 — REQ-WS-053이 막으려는 것과 같은 결함 계열이다.

### 7.3 키는 출하 템플릿을 따른다

`author`(단수, 값 타입으로 복수 표현), `registration`(레지스트리 다형성), `acknowledgements`(신규). 병렬 명칭을 만들지 않는다. `registration`은 ClinicalTrials.gov 값에만 NCT 검증을 적용하고 그 외에는 **어떤 형식 검증도 하지 않는다** — 정의하지 않은 형식으로 유효 입력을 거부하지 않기 위함이다.

## 8. 매니페스트 갱신 — 키 단위 스플라이스

`shared/frontMatter.ts`의 발상("파싱은 위치를 알아내는 데 쓰고, 쓰기는 그 위치만 건드린다")을 매니페스트에 적용한다. 단 `frontMatterRange`는 **블록 전체** 범위를 반환하므로 그대로 쓸 수 없다 — 주석·키 순서·모르는 키를 보존하려면 **키 단위 범위 계산이 신규로 필요**하다.

이 방식은 라운드트립 보존 파서 없이 REQ-WS-003을 만족시키고, 새 의존성을 도입하지 않는다.

## 9. 프로젝트 없음 상태 — 축퇴가 아니라 1급 상태

정본이 front matter이므로 프로젝트 없음 상태에서 비는 것은 **기본값 계층 하나뿐**이다. 감시·확정·조정·IME 게이트·메타데이터가 모두 그대로 동작한다. C-1이 어느 요구가 이 상태에서 완전 동작해야 하고 어느 것이 본질적으로 프로젝트 조건부인지 열거한다.
